## 一、结论摘要

**分晓目前无法支持这两个文件夹里的全部表格。** 53 份的实测分布：

| 结果 | 份数 | 含义 |
| :--- | ---: | :--- |
| 完整正确导入 | 2 | 「全部考生成绩汇总.xls」「九A1 学生小题明细表.xlsx」 |
| 部分可用 / 语义错误 | 4 | 多科目工作簿只读了第一张表，或把题型、题号当成科目 |
| 误判为成绩表 | 6 | 临界生、优秀生学困生、缺考名单被当成班级成绩表，静默生成不完整成绩条 |
| 直接崩溃 | 2 | 缺「考号」列时 ClosedXML 越界，抛英文异常 |
| 正确拒绝 | 39 | 统计/分析报告，本身不含学生个人成绩，拒绝是正确行为 |

三个真正的缺口：

1. **多工作表只读第一张**：`所有单科成绩报告.xls`（10 个科目表）只导入语文；`所有班级学生小题得分明细.xlsx`（10 个科目表）只导入语文。
2. **名单型表格被误判**：只要表里有「姓名」列就按班级成绩表处理，导致 6 份名单被静默导入（全班 993 人里只出一小撮人的成绩条）。
3. **缺考号列时崩溃**：`ReadWideHeader` 用 `Cell(row, 0)` 读不存在的考号列，任何「有姓名、无考号」的 xlsx 都会抛 `ArgumentOutOfRangeException`。

另有一批**不属于分晓范围**的文件：试卷分析（作答详情/大题分析/小题分析）只有班级逐题均分与得分率，没有学生个人得分；统计对比（班级/学科/分段/等级/平均分）和名单（临界生/优秀生学困生/缺考）也不产生学生成绩。这些文件不需要支持，但必须给出准确的中文拒绝理由，而不是被误导入。

## 五、缺陷与根因

### P0-1 缺「考号」列时崩溃（2 份）

[GradeSheetImporter.cs](file:///d:/Documents/TeachCraft/vendor/gradestrip/src/GradeStrip.Core/Import/GradeSheetImporter.cs#L535) 用 `sheet.Cell(r, examNoCol > 0 ? examNoCol : 0)` 取考号单元格。ClosedXML 的列号从 1 开始，传 0 直接抛 `ArgumentOutOfRangeException`（英文），界面只能兜底成「处理失败：…」。

`ReadSubHeader` 的 [同款写法](file:///d:/Documents/TeachCraft/vendor/gradestrip/src/GradeStrip.Core/Import/GradeSheetImporter.cs#L327) 也有同样问题，只是该分支要求至少 3 个「得分」列，本次没被触发。

### P0-2 一个工作簿多张科目表时只读第一张（4 份）

- xlsx 路径：[GetCandidateSheets](file:///d:/Documents/TeachCraft/vendor/gradestrip/src/GradeStrip.Core/Import/GradeSheetImporter.cs#L154-L171) 按「汇总 → 简表/成绩 → 其余」排序后逐张试读，[ReadSheet](file:///d:/Documents/TeachCraft/vendor/gradestrip/src/GradeStrip.Core/Import/GradeSheetImporter.cs#L94-L109) 读到第一张合格表就 `return`。
- xls 路径：[TryLoadTabularXls](file:///d:/Documents/TeachCraft/vendor/gradestrip/src/GradeStrip.Core/Import/GradeSheetImporter.cs#L1844-L1862) 同样在第一个成功的 DataTable 上返回。

「所有单科成绩报告」的工作表名恰好是语文/数学/英语…，于是永远只读语文，且**没有任何提示**说只导入了 1/10 科。界面只会显示「993 人 · 1 科」，老师不一定意识到其余九科丢了。

### P0-3 名单型表格被误判为班级成绩表（6 份）

[ReadWideHeader](file:///d:/Documents/TeachCraft/vendor/gradestrip/src/GradeStrip.Core/Import/GradeSheetImporter.cs#L424-L593) 的判据只有「前 10 行里有『姓名』」。只要命中，任何行数都会被当成一个班级：

- 临界生对比：姓名 + 总分（159 / 112 / 112 / 220 人）
- 优秀生学困生对比：前 10 + 后 10（20 人）
- 缺考学生汇总：姓名 + 缺考科目（33 人）

导入后 `Subjects` 可能只有「单科」「缺考科目」，`ClassName` 取第一个学生的班级（九年级15班/九年级6班/九年级13班…全是偶然值）。老师若直接导出成绩条，会得到一份「挑出来的一小撮人」的成绩条，且界面上看不出异常——这比报错危险得多。

### P1-1 明细型表格语义错（3 份）

[单科判定分支](file:///d:/Documents/TeachCraft/vendor/gradestrip/src/GradeStrip.Core/Import/GradeSheetImporter.cs#L468-L480) 把「客观分/主观分/单选题/解答题/作文」和纯数字表头都当科目或单科标记：

- `所有班级学生小题得分明细.xlsx`：27 个「科目」，其中只有客观分/主观分/作文/题号有值，总分是「该科总分」而非考试总分。
- `学生答题明细_…_九年级A1.xlsx`：选中的是「客观题填涂」表，10 个题号列是选项字母，全部解析为空。
- `学生小题明细表.xlsx`（九A1）：主分数可用，但题号→选项/得分没有进入 `StudentRecord.QuestionScores`，学生详情页无法展示逐题得分。

`QuestionScores` 目前只在「单科个人成绩单」路径里填充，明细表这条路径完全没接上。

### P1-2 元数据解析（普遍存在）

- `ExtractExamName` 用 `\d{4}\s*[-－]\s*\d{4}\s*学年.*$` 贪到行尾，把「】所有班级语文学生小题得分明细」「】九年级A1数学学生小题得分明细」都算进考试名。
- `ClassName` 取第一个学生的班级；整年级文件（全部考生成绩汇总 993 人、所有单科成绩报告）因此被标成「九年级13班」「九年级1班」。
- 跨班文件的「班级」本应留空或标注为全年级，而不是抓阄。

### P2 交互与提示

- 界面只允许选择 `.xlsx / .xls / .xlsm`，不支持 zip，也没有「请先解压」的提示；老师拖入 zip 只会在文件选择器里看不到。
- `ImportOptions.SheetName` 已实现但界面没有暴露，多表工作簿无法手动指定工作表。
- 「全部考生成绩汇总」的进退步列存在但全为 `-`，提示语仍说「未包含单科进退步数据」，措辞不准确。
- `.xls` 与 `.xlsx` 走的是两套**重复实现**（DataTable 版 `TryReadTwoLevelHeaderDataTable` / `TryReadWideDataTable` 与 ClosedXML 版 `ReadSubHeader` / `ReadWideHeader`），任何识别规则改动都要成对改，否则两种格式行为不一致——本次 A02/A06（xls）与 A07（xlsx）的错误就是同源。

## 七、建议的修复顺序

1. **修崩溃**：考号列缺失时跳过，不再 `Cell(row, 0)`；同时补一条「工作簿无学生成绩」的中文提示。
2. **加导入前的完整性校验**：命中「临界生 / 优秀生 / 学困生 / 缺考 / 需关注 / 类别」等表头，或有效分数行数明显少于班级规模、或科目列全空时，拒绝导入并说明原因。先堵住最危险的静默错误。
3. **合并同簿多科目表**：xls 与 xlsx 两条路径都改为「识别所有科目表 → 按姓名 + 考号合并成一份 `ExamData`」；工作表名命中已知科目时直接当科目标签。
4. **明细表支持**：题号/选项列写入 `QuestionScores`，科目名从标题括号或工作表名提取；`客观分/主观分/题型` 不再当科目。
5. **元数据修正**：考试名在「段考/考试/测试」等词后截断；跨班文件不写 `ClassName`。
6. **交互**：选择 zip 时提示先解压；多表工作簿允许选表；拒绝理由区分「统计表」「名单」「无个人得分」。

### TeachCraft 构建踩坑（新增）

vendor 未列入 TeachCraft.slnx 时，`dotnet build <slnx>` 会用默认 Debug 配置编译未列管的传递引用项目；而 NuGet restore 只在 restore 时刻按当时 Configuration 求值条件项元数据并冻结进与配置无关的 `obj/project.assets.json`。叠加后果：Release restore 冻结 `AvaloniaUI.DiagnosticsSupport` 的 `IncludeAssets=None` → Debug 编译缺包 → vendor Program.cs `#if DEBUG` 内 `.WithDeveloperTools()` 报 CS1061（是否触发取决于最后一次 restore 的配置，抽奖式）。修复：把 vendor GradeStrip.Core / GradeStrip.App 显式列入 slnx（`/vendor/` Folder），由 sln 配置映射接管。上游同类隐患（`IncludeAssets` 条件元数据本身逐配置抽奖）建议改为无条件引用——Release 编译本不触发 `#if DEBUG` 分支；本轮不动上游已提交内容。
