# 02 · 架构与技术栈

## 解决方案

```
TeachCraft.slnx
├─ src/TeachCraft.App      Avalonia 桌面端（壳 + 抽屉 + 分晓 / 归位入口）
├─ src/TeachCraft.Core     与 UI 无关的图片 / PDF 工具引擎
├─ src/SeatGrid.App        归位座位表窗口（名单、网格、设置、预览）
├─ src/SeatGrid.Core       名单识别、排座、PNG/PDF/Excel/配置导出
├─ src/ClassBlock.App      时序课程表窗口（总表、班级列表、课表、设置）
├─ src/ClassBlock.Core     总表识别、班级课程提取、PNG/PDF 渲染
├─ vendor/gradestrip       分晓 App/Core 只读快照（2026-10-22 同步）
└─ tests/TeachCraft.Tests  19 项 xUnit 端到端工具测试
```

- `Directory.Build.props` 统一版本号、产品名、作者。
- `TeachCraft.App` 引用 `TeachCraft.Core` 与 `vendor/gradestrip/src/GradeStrip.App`。
- 关键原因：CI 不能访问仓库外的 `D:\Documents\Grade-Organizer`，所以把分晓源码 vendor 进仓库；`vendor` 只读，升级时整体同步。

## 分层边界

```
MainViewModel / ToolItemViewModel
        │  选择文件、选项、输出路径
        ▼
ToolRequest (Core)  ──►  ToolDispatcher.Run
        │                     │
        │                     ├─ ImageToolbox
        │                     ├─ PdfToolbox
        │                     └─ CjkFont
        ▼
ToolboxException（中文可读消息）
```

- `ToolKind` 决定 UI 选项与 Core 分支，工具 ID 与 `ToolKind` 是稳定契约。
- UI 不直接调用 Skia/PDF API；Core 不感知 Avalonia。
- 长任务通过 `Task.Run` 执行，`Progress<int>` 回 UI。

## 中文字体

- UI：Anthropic Serif（拉丁）+ SimSun / 系统宋体兜底；正文微软雅黑 UI。
- Word→PDF：`CjkFont` 在运行时注册系统 CJK 字体（DengXian → SimHei → Microsoft YaHei → SimSun）；
  找不到时回退 Lato（CI 环境可能没有中文字体，相关测试会跳过）。
- 这是为了绕开 QuestPDF 2026 默认不加载系统字体的行为。

## 分晓的运行方式

- `OnLaunchGradeStrip` 直接 `new GradeStrip.App.Views.MainWindow { DataContext = new MainViewModel() }.Show()`，同进程。
- 分晓 XAML 依赖 App 级笔刷 / 字体资源（`InkBrush`、`MonoFont` 等），这些已复制进 `TeachCraft.App/App.axaml`。
- 分晓样式（按钮、卡片、导航）也在 `App.axaml` 中保留，因此两个窗口观感一致。
- **vendor 的 `GradeStrip.App` 以 `Library` 编译**：如果保留上游的 `WinExe`，framework-dependent 发布会报 `NETSDK1151`（自包含可执行文件不能被非自包含可执行文件引用）。发布 target 仍会兜底删除可能残留的 `GradeStrip.App.exe` 与 `runtimeconfig.json`。

- 发布目录里的 `GradeStrip.App.exe` / `runtimeconfig.json` 由 target 删除，只保留 DLL。
- **归位**是独立窗口，由工具箱同进程打开；数据管线为 `RosterImporter → SeatingEngine → SeatChartComposer → Renderer / Excel / Config`，界面与三种导出共用同一份 `SeatChartDocument`。
- 归位只在屏幕上用 Avalonia 控件绘制；导出走 SkiaSharp（PNG）与 QuestPDF（把 PNG 嵌入 A4 PDF）；Excel 走 ClosedXML。
- **时序**同样是同进程独立窗口；数据管线为 `MasterScheduleImporter → TimetableBuilder → TimetableRenderer`。总表只读 `.xlsx`（ClosedXML），合并单元格通过 `MergedRange().FirstCell()` 解析；界面预览、PNG、PDF 共用同一个 `ClassTimetable`，屏幕上显示的就是渲染后的位图，保证所见即所得。

## 平台与原生库

- SkiaSharp：win-x86/x64/arm64、linux-x86/x64/arm/arm64、macOS universal。
- PDFium：win-x86/x64/arm64、linux-x86/x64/arm/arm64、osx-x64/arm64。
- QuestPDF：win-x86/x64/arm64、osx-x64/arm64、linux-x64/arm64（**无 linux-arm**）。
- 因此矩阵不包含 `linux-arm`；这一点已写入 AGENTS.md，不能悄悄宣称支持。
- Windows 单文件发布已验证：Word→PDF、PDF 转图片在 `PublishSingleFile + IncludeNativeLibrariesForSelfExtract` 下正常。
