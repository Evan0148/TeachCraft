# 06 · 决策与踩坑记录

## 选型

### 织序 `.xls` 导入用 NPOI（2026-10-26）
ClosedXML 只能读 xlsx；织序要支持老师的 `.xls` 老文件，选了 NPOI 2.8.1：HSSF 读 `.xls` 能保留合并区域（`sheet.NumMergedRegions`），复制值 + 合并区域到内存 `XLWorkbook` 后走原有解析管线，无需改任何解析代码。注意三点：
1. NPOI 构建期要求显式 `<AcceptNPOIOSMFLicense>true</AcceptNPOIOSMFLicense>`，否则警告。
2. NPOI 传递依赖 `System.Security.Cryptography.Pkcs / Xml 10.0.10`（各有漏洞公告），已在 `GradeWeave.Core.csproj` 钉到 10.0.14。
3. `HSSFWorkbook(stream)` 读完即可关流；ClosedXML `XLWorkbook(stream)` 同理（曾因流未关闭导致测试清理目录时 IOException）。

### PdfSharpCore 1.3.67 → PDFsharp 6.2.4（2026-10-26）
`PdfSharpCore 1.3.67` 传递依赖 `SixLabors.ImageSharp 1.0.4`，NuGet 审计命中 8 条已知漏洞（3 条高危、5 条中危，NU1902/NU1903）。改用 MIT 的 `PDFsharp 6.2.4`：合并、拆分、页数读取能力相同，且不再引入 ImageSharp。**不要升到 6.5**：6.5 改为 AGPL，未调用 `SetAgplLicense` 时运行直接报 `The loaded license is not valid`（已实测）。PDFsharp 6.2.4 仍声明 `System.Security.Cryptography.Pkcs >= 8.0.1`，必须显式钉 `10.0.14`，否则会换成一个新的高危/中危警告。PDF 渲染仍交给 PDFtoImage。

### PDFsharp 6.5 → PdfSharpCore 1.3.67（历史）
PDFsharp 6.5 变为 AGPL-3.0，且运行时报 `The loaded license is not valid`，需要显式 `PdfSharpLicense.SetAgplLicense()`。为避免 AGPL 传染与发布风险，当时改用 MIT 的 PdfSharpCore。该方案已由上一节替代。

### PDFtoImage 5.4 → 5.2.0
5.4 依赖 SkiaSharp 4.150.1，而 Avalonia 12.1.4 绑定 SkiaSharp 3.119.4，NuGet 报 NU1605 降级错误。5.2.0 依赖 SkiaSharp 3.119.1，与 Avalonia 兼容。**升级 Avalonia/PDFtoImage 时必须成对验证。**

### 图片合成 PDF 改用 QuestPDF
PdfSharpCore 的 `XImage` 对 WebP/部分 PNG 支持不稳；QuestPDF 基于 Skia，能直接吃 WebP，还能自动横竖切换，因此图片合成走 QuestPDF，只有合并/拆分留在 PDF 库。

### 中文字体
QuestPDF 2026 默认不加载系统字体，未注册时直接抛「font family not available」。`CjkFont` 在运行时按平台注册 DengXian / SimHei / Microsoft YaHei / SimSun；找不到时回退 Lato，测试会跳过中文用例。**不要把中文字体检测删掉**，否则非中文 CI 环境会误报。

## 织序

### 自动保存用 JSON 快照比较，不靠零散脏事件（2026-10-26）
织序的工程修改分散在教研、会议、走班、手动放课、活动、作息确认等路径，逐个补 `ProjectChanged` 容易漏。自动保存用 2 秒 `DispatcherTimer` + 全局脏标记/心跳：定时在 UI 线程序列化 `WeaveProject`，与上次 JSON 比较，只有变化才后台原子写入。这样新增修改入口不需要额外接线，心跳也能兜住漏发事件；`IsBusy` 时跳过，避免读到调度器正在改的半成品。有 `.weave.json` 路径时原子写回原文件，没有路径或写失败才落到 `%LOCALAPPDATA%` 恢复文件，绝不覆盖导入的工作簿。关闭窗口同步补写一次，UI 状态栏只报告自动保存自身状态，不覆盖老师正在看的操作提示。

### 作息时间表参考 ClassIsland，但只取最小模型（2026-10-26）
ClassIsland 的 `TimeLayout` 用「时间点列表 + 类型（上课 / 课间 / 分割线 / 行动）」描述一天，课表只与上课时间点一一对应。织序只借鉴这个心智模型和交互（时段列表、详情编辑、按真实时长绘制的时间轴），不引入行动组、触发器、临时层、缩放与拖拽改时间；行类型收敛为 `Lesson / MorningReading / Break / NoonStudy / Lunch / Rest / EyeExercise / AfterSchool / EveningStudy / Routine`。确认门槛用内容签名而不是布尔标记：`ConfirmedSignature` 是「类型 + 名称 + 起止」的 SHA-256，任何一行改动都会让 `IsConfirmed` 失效，避免出现「已确认但实际已改」的假状态。作息只描述一天，不按星期分表；五天课表仍由 `WeaveProject.Lessons` 承担。

### 手动放课写入固定课（2026-10-26）
05 步点击课程格的手动放课不能写成普通 `Lessons`：`PermutationScheduler.WriteLessons` 会清掉所有非 `IsFixed` 记录，重排一次就丢。`LessonPlacementService.Place` 统一写 `IsFixed=true, Note="手动放课"`，`BuildTasks` 会从对应任课课时中扣除，重排时保留。活动格与走班格（固定区间或 `ResolvedSlots`）直接拒绝，教师冲突 / 教研会议 / 超课时只写警告交给 `ConflictAnalyzer`，不替老师静默换课。

### 走班时间默认在生成时安排（2026-10-26）
新建走班组默认 `IsFlexible=true`，避免老师先猜节次。`ConstraintRules.TryGetLayeredGroupAt` 原来只看 `DayIndex/StartPeriod/EndPeriod`，自动组生成后落位在 `ResolvedSlots`，导致手动放课、清除和格子预览认不出走班时段；现统一用 `IsGroupAt`（固定看区间、自动看落位数）判定。生成后状态栏与格子必须显示「N 个班同节走班」，让老师知道同组参与班都在上走班课。

### 教师分工改为先建名单再分工（2026-10-27）
原分工窗口只有「班级 × 学科」一张表，20 个班 × 9 个学科要逐格点 180 次，而且直接在格子里打字会隐式创建教师。现在把**教师名单**作为默认第 1 步：先维护姓名 + 学科（支持每行「姓名,学科」批量粘贴），班级 / 学科格的教师输入改为按学科过滤的名单下拉，新增但未任课的教师也会在保存时写入 `Teacher` 档案。五种视角共享同一份 `Rows` + `TeacherRoster` 草稿，切换视角只刷新派生集合，不得重建草稿或提前写回；删除教师前必须解除任课、班主任与课表 / 走班 / 会议 / 活动引用，避免悬空 ID。

### Avalonia 滚动条覆盖行尾按钮（2026-10-26）
Fluent 主题的纵向滚动条是覆盖在内容右缘上的（内容 Presenter 横跨滚动条列），行尾的「删除 / 放入本格」按钮会被压住。修法是给 ScrollViewer 的内容加右边距（`Margin="0,0,14,0"`），让滚动条落在留白里；`ScrollViewer.Padding` 没用——它连同滚动条一起内缩，仍会盖住内容。另外 NumericUpDown 列宽低于 96 时，并排的上下调按钮会把数值挤没，周课时列至少留 96。

## 分晓集成

### 同进程打开
直接 new `GradeStrip.App.Views.MainWindow` 最稳：与工具箱共享进程、字体与资源，不需要外部 exe、不需要安装路径。分晓的 App 级 StaticResource 已复制到 TeachCraft 的 App.axaml。

### 为 CI 做 vendor
TeachCraft 原先通过 `..\..\..\Grade-Organizer` 引用分晓；云端仓库没有这个目录。现在把 `GradeStrip.App` 与 `GradeStrip.Core` 快照到 `vendor/gradestrip`（上游 2026-10-22 版本），发布产物仍然只包含 DLL。同步方式写在 AGENTS.md。

### vendor 转正为 src 一等项目（2026-10-24）
分晓的性能优化（异步、单次解析、虚拟化、页签释放）在上游完成后，决定终止快照模式：`vendor/gradestrip` 删除，`GradeStrip.App` / `GradeStrip.Core` 移入 `src/` 与归位、时序并列，命名空间保持 `GradeStrip.*` 不变，之后直接在本仓库开发；上游 `Evan0148/GradeStrip` 转为独立应用。顺带把 `AvaloniaUI.DiagnosticsSupport` 的按配置条件引用改为无条件 + `PrivateAssets=All`——条件版在 Release 还原后曾让 `WithDeveloperTools()` 报 CS1061。AGENTS.md 第五节已改写。

### 上游仓库删除（2026-10-24）
vendor 转正后，`D:\Documents\Grade-Organizer` 同步核对（45 个实质文件哈希一致，仅 csproj 有意差异）确认无遗漏，且工作区干净、全部推送 GitHub（HEAD == origin/main）后删除本地目录。删除前把 `tests/GradeStrip.Tests`（102 项）与 `tests/fixtures`（7 份合成数据）迁入本仓库并跑绿，CI 测试步骤改为依次跑两个测试项目。上游 GitHub 仓库保留全部历史，需要时可 re-clone。注意：fixture 定位用「测试程序集向上 4 级找 `tests/fixtures`」，测试项目在 `tests/` 下的目录深度不能变。

### 发布时删掉分晓的 apphost
ProjectReference 会把 `GradeStrip.App.exe` 一并复制到输出目录。`TeachCraft.App.csproj` 的 `RemoveGradeStripAppHost` target 在 `AfterTargets="Publish"` 删除它，避免用户误以为有两个程序。

### vendor 必须是 Library
CI 首轮里所有 framework-dependent 构建都报 `NETSDK1151: The referenced project ... is a self-contained executable`。原因是分晓快照保留了上游的 `OutputType=WinExe`，在 `dotnet publish` 时会跟随 RID 自包含。把 vendor 的 `GradeStrip.App` 改成 `Library` 后，14 个矩阵包都能正常生成。

### macOS 签名被 QuestPDF 字体档案卡住
`QuestPDF.Fonts.Lato.br` 放在 `Contents/MacOS/` 时，`codesign` 会把它当作未签名的子代码，报 `code object is not signed at all`。修复：签名前把它移到 `Contents/Resources/`。已验证删除该档案后 Word→PDF 仍能生成（应用始终显式使用中文 CJK 字体）。

### 改 AssemblyName 会打断 avares
把 `AssemblyName` 从 `TeachCraft.App` 改为 `TeachCraft` 后，所有 `avares://TeachCraft.App/...` 都会失效。已将 App.axaml 的字体 URI、ProjectPanelView 的截图 URI 全部改为 `avares://TeachCraft/...`。以后改程序集名务必全局搜索 `avares://`。

### vendor 内嵌后 `WithDeveloperTools` 报 CS1061
同步上游 App 后，`Program.cs` 仍调用 `.WithDeveloperTools()`；上游 csproj 对 `AvaloniaUI.DiagnosticsSupport` 设了 `IncludeAssets=None`（非 Debug）。vendor 项目由工具箱间接构建，restore 与 build 的 Configuration 可能不一致，导致编译资产被排除、报 CS1061。修复：vendor 的 csproj 保留包引用但删除 `IncludeAssets` / `PrivateAssets` 条件。若再次同步 csproj，记得重新处理。

## 构建

### VS 报 CS1061 `WithDeveloperTools`
模板残留调用，项目没有引用 `AvaloniaUI.DiagnosticsSupport`。CLI 因分晓项目的传递引用偶然通过，VS 单独分析时报错。已移除；若需要调试面板再单独加包。

### 单文件 + 原生库
Windows 上 `PublishSingleFile=true` 必须配 `IncludeNativeLibrariesForSelfExtract=true`，否则 PDFium / QuestPDF 原生库加载失败。已验证 Word→PDF、PDF→图片在单文件下可用。
macOS 不能开这个开关（Avalonia 官方说明会与 CoreCLR 冲突），所以 DMG 里保留 dylib 并逐个 ad-hoc 签名。

### PDB 体积
单文件发布目录会出现 `libSkiaSharp.pdb`（约 84MB）与 `libHarfBuzzSharp.pdb`（约 21MB）。CI 打包前、Inno 打包前、macOS 签名前都删除 PDB。

### 构建时 exe 被占用
多次 UI 自动化测试会残留 `TeachCraft` 进程，锁住 Debug exe。构建前先 `Get-Process TeachCraft | Stop-Process -Force`。

## UI / 交互

### 缩放工具的默认值冲突
初版同时给了宽高 1600/1000 与百分比 50，而 Core 优先百分比，用户改宽高却不生效。现在：宽度或高度一旦有值就清空百分比；百分比一旦有值就清空宽高。构造时 resize 工具默认只保留 50%。

### 搜索时隐藏空分类
搜索无命中时，分类标题与列表一起隐藏，只显示空状态，避免出现「00 件工具」的尴尬空区。

### PNG 压缩不夸大
PNG 无 lossy 画质，压缩收益主要靠缩小边长。结果文案会明确写出这一点，不假装「画质 45 能压一半」。

### 水印颜色
固定白字在浅色图片上几乎看不见。现在采样图像平均亮度：浅图用墨色字 + 白描边，深图用白字 + 黑阴影。

### 分段按钮不要固定宽度
分晓导出设置的「排名维度 / 对比基准」曾用固定 `Width=92/142` + 星号 `Grid` 平分三列；「上一场」三个字加左右内边距超过列宽，文字溢出并压住相邻按钮。改为 `Border` + 横向 `StackPanel`，按钮 `MinWidth=42`、`Padding=10,0`，按内容自适应宽度。

### 原生文件对话框自动化
UIA 能确认对话框确实打开（`文件名(N):`、`打开(O)`、`取消` 都在树里），但现代 Shell 对话框的编辑框无法稳定用 ValuePattern 写入，SendKeys 在 PowerShell 7 下也不可靠。**这不是产品缺陷**；最终由人工点选验证。测试通过 `--selftest` 跳过对话框，覆盖「选完文件之后的完整处理链路」。

## 分晓大数据量性能优化

### 问题定位
3000 人 × 10 科 × 59 列实测：导入 0.7s、概览+成绩条重建 1.07s、导出 5.2s / 950MB 分配。用户报告的 1GB+ 常驻内存主要来自无虚拟化的可视树（报表 3000 行 × 约 122 控件 ≈ 36 万）与 `BuildStrips` 一次产生的约 13 万个画刷，而不是成绩数据本身（数据通常 <200MB）。

### 处理方式
- 导入、报表、导出全部异步：Core 解析在 `Task.Run`，UI 线程只做集合应用；`IsBusy` 禁用入口，失败复位。
- 单次解析：`.xls` 一次 `AsDataSet`、`.xlsx` 一次 `XLWorkbook`；个人成绩单 / 科目分表探测复用同一对象；报表用 `Load(path, out kind)` 一次打开。
- 报表表格与成绩条预览换成 `ListBox` 虚拟化，列表自身限定高度，横向滚动留给外层；切走页签释放集合，切回按需重建。
- 长列表用 `RangeObservableCollection.ReplaceAll` 一次 Reset；`Palette.Brush` 按色值缓存；补排名改 `GroupBy` 一次计数。
- 导出缓存 `XLColor`，`SaveAs` 后先释放 ClosedXML 再跑 OpenXML 后处理。

### 实测（3000 人，Release）
- 导入热约 0.9s；概览构建后 `StripItems=0`（懒构建），切到成绩条才生成 3377 项。
- 报表 3000×30：`Load` 271ms（优化前 478ms），90,000 单元格 VM 约 0.3s。
- 导出 5.12s / 947MB 分配 / 峰值工作集 156MB；分配未降 30%，主因是 ClosedXML 单元格与样式对象本身。
- 截图只渲染 16 行报表与 3–4 张成绩条，滚动条正常；3000 人成绩条页应用峰值约 394MB。

### 注意
- 页签释放后 `Students` 可能为空；`--shot --student` 截图前必须先 `Section = 0` 重建（已处理）。
- `ObservableCollection` 的批量替换只发一次 Reset，不要再改回逐条 Add。
- vendor 的 `GradeStrip.App.csproj` 必须保持 `OutputType=Library`，且 `AvaloniaUI.DiagnosticsSupport` 用无条件引用，否则 Release 下 `WithDeveloperTools()` 报 CS1061。

## 2026-10-27 全链路性能修复

### 结论
三轮子代理审计（5 模块 + 5 横切 + 4 复核）确认：主要瓶颈是重复打开/物化工作簿、UI 线程全量重建、位图多份缓冲与自动保存缺少版本守卫，不是零散微优化。

### 已落地
- 分晓：个人成绩单与分科合并共用一次 `DataSet`；排名回填改频次计数 O(N)；拖拽分类结果复用，去掉重复探测与空内联报表读取。
- 织序：后台编排期间右键 / Delete 加 `IsBusy` 门禁；自动保存改为 UI 线程取快照、后台序列化，落盘带 `(sessionId, version)` 守卫，旧快照不会覆盖新内容；总表预建课程/走班/活动/冲突索引并复用 `Border`，隐藏步骤不再重建。
- 时序：预览 250ms 防抖 + `CancellationToken`，PNG 解码移到后台，`RenderPngBytes` 支持取消，关窗取消在途渲染。
- 归位：滑块按下暂停、松手一次性重建；`SeatChartRenderer` 按渲染缓存复用 `SKPaint`/`SKFont`，空座虚线 `PathEffect` 只建一次。
- PDF：`PdfToImages` 改用 `ToImages` 一次加载整份文档，逐页直接 `Encode` 到文件流，DPI 上限 300。
- 发布：R2R 实测自包含单文件 159MB→274MB（+115MB）、框架依赖 49MB→111MB（+62MB），启动收益不足以抵消包体代价，未启用。

### 注意
- 自动保存写入必须带 `(sessionId, version)`，旧版本写盘要被跳过；不要退回仅按时间串行化。
- 织序总表格子缓存以「班级 Id + 节次」为签名；换工程或改节次数时必须让签名失配并全量重建。
- UI 截图模式（`--*-shot`）要逐次单独启动并等待，连续 `Start-Process -Wait` 容易因窗口会话冲突超时。

## 2026-10-27 .xls 测试资产隐私清洗

### 踩坑：两字真名被误判为扫描伪影
首轮字节清洗把「两字真名 + _成绩单」的报告属主标题判成伪影而跳过：行级 / 长串模式扫描对独立 2 字短名不敏感，且它不属于任何名单行。hexdump 解析 SST 后才定性为真实条目并补擦。教训：字节层清洗必须以 SST 条目结构解析 + 活引用交叉兜底，启发式扫描只能当快筛；结构逐条走查优先于模式匹配。

### SST 条目机制
- 条目结构：`cch(2B LE) + grbit(1B, 01=16-bit) + data(2×cch 字节)`，条目背靠背；奇数 cch 使后续条目奇偶错位，出现偶 / 奇对齐两族。
- u16scan 报告的偏移是文本索引：E 报告值 r → 真实字节 `2r`，O 报告值 r → 真实字节 `2r−1`。
- 「姓名_成绩单」标题的下划线断开 CJK run，姓名独立成条目——短名因此长期漏网。

### 工具链与流程（temp/，禁入库）
- `temp/xls-synth`：Program.cs 四模式 rescan / u16scan / apply / scrub；UTF-16LE + GB18030 双对齐、三层数字扫描兜底考号。
- 流程：token 清单（`scrub-tokens.txt`，144 项）→ dry 复扫 0 命中 → real 擦除 → u16-after 全量细审（剩余 run 白名单归类）→ NPOI 金丝雀（解析结果不变）→ 全量测试。
